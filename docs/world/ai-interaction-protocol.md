# 绯界 AI 交互协议（AI Interaction Protocol）

## 目的

本文档记录绯界内部各个房间与 AI 交互时应遵循的统一逻辑。

核心原则：

> 房间负责创造世界事件，AI 负责延续故事，记录系统负责保存共同记忆。

酒馆、旅行小兔、未来图书馆等功能都应尽量复用这一套流程。

---

# 一、基础数据模型

每一次世界事件都应形成一条记录（Record）。

基础结构：

```ts
{
  id: string,
  createdAt: string,
  type: string,
  data: object,
  note: string,
  noteUpdatedAt: string | null
}
```

字段说明：

- `id`
  - 唯一记录编号
  - 用于 AI 精确定位目标记录

- `createdAt`
  - 创建时间

- `type`
  - 记录类型
  - 例如：tavern、travel、library

- `data`
  - 世界事件本身的数据

- `note`
  - AI 后续创作内容存储位置
  - 不覆盖原始事件

- `noteUpdatedAt`
  - AI 内容更新时间

---

# 二、统一交互流程

## 1. 创建事件

用户或随机系统触发事件：

```
点击按钮
↓
随机生成世界内容
↓
生成 Record
↓
保存本地历史
```

例如：

酒馆：

```
点酒
↓
生成酒签
↓
保存调酒记录
```

旅行小兔：

```
开始旅行
↓
随机目的地
↓
发现景色/动物/特产
↓
生成旅行记录
```

---

# 三、发送给 AI

所有房间统一采用：

```
Record
↓
生成读取指令
↓
发送给 AI
↓
AI 根据世界设定续写
```

发送内容应包含：

- 记录 ID
- 记录类型
- 当前事件数据
- 读取钥匙
- 回复钥匙
- 写入目标

要求 AI：

- 读取对应记录
- 不修改原始数据
- 只追加 note 内容
- 保持世界观一致

---

# 四、收取 AI 内容

统一流程：

```
读取云端记录
↓
寻找对应 ID
↓
比较 note 更新时间
↓
合并最新内容
↓
更新本地记录
```

规则：

- AI 内容只能追加到 note
- 不覆盖事件数据
- 不删除历史记录

---

# 五、导入与导出

所有房间支持 JSON 档案。

导出：

```
本地记录
↓
JSON 文件
↓
用户保存
```

导入：

```
JSON 文件
↓
校验结构
↓
合并历史
↓
更新记录
```

---

# 六、房间扩展规范

## 酒馆

事件：调酒

数据：

- 酒名
- 标签
- 酒保
- 客人
- 随杯手记

AI 内容：

- 续写酒馆故事

---

## 旅行小兔

事件：旅行

数据：

- 大陆
- 国家
- 城市
- 地点
- 遇见的动物
- 发现的景色
- 带回的物品
- 品尝的美食

AI 内容：

- 旅行信件
- 明信片
- 旅途故事

---

# 七、设计理念

绯界不是多个孤立应用。

所有房间共享同一个核心：

```
创造记忆
↓
记录世界
↓
邀请 AI 回应
↓
形成新的故事
```

每一次互动，都是世界留下的一页。
