# 绯界 AI 交互协议（AI Interaction Protocol）

## 目的

本文档记录绯界内部各个房间与 AI、MCP、记录系统交互时应遵循的统一逻辑。

核心原则：

> 房间负责创造世界事件，AI 负责延续故事，记录系统负责保存共同记忆。

酒馆、旅行小兔、日记本、未来图书馆等功能都应尽量复用这一套流程。

---

# 一、基础数据模型

每一次世界事件都应形成一条记录（Record）。

```ts
{
  id: string,
  createdAt: string,
  type: string,
  data: object,
  note: string,
  noteUpdatedAt: string | null
}
```

字段说明：

- `id`：唯一记录编号，用于 AI 精确定位目标记录
- `createdAt`：创建时间
- `type`：记录类型，例如 tavern、travel、journal、library
- `data`：原始世界事件数据
- `note`：AI 后续创作内容存储位置，不覆盖原始事件
- `noteUpdatedAt`：AI 内容更新时间

---

# 二、统一事件流程

```
点击按钮
↓
生成世界内容
↓
生成 Record
↓
保存本地历史
↓
等待 AI 延续
```

例如：

酒馆：

```
点酒
↓
生成酒签
↓
保存调酒记录
```

旅行小兔：

```
开始旅行
↓
随机目的地
↓
发现景色/动物/特产
↓
生成旅行记录
```

日记本：

```
记录心情
↓
保存个人记忆
↓
等待 AI 回应
```

---

# 三、AI 上下文读取规范

AI 进行创作前，应优先读取：

1. 当前事件记录
2. 当前房间规则
3. 世界书（World Bible）
4. 角色卡与人物设定
5. 关系设定
6. 近期记忆
7. AI 自主补全内容

AI 不是世界创造者。

世界由世界书、文明记录与事件数据决定。

AI 负责：

- 解释世界
- 延续故事
- 丰富细节
- 生成回应

---

# 四、发送给 AI

所有房间统一采用：

```
Record
↓
生成读取指令
↓
发送给 AI
↓
AI 根据世界设定续写
```

发送内容应包含：

- 模块名称
- 记录编号
- 记录 ID
- 当前事件数据
- 读取钥匙
- 回复钥匙
- 写入目标

AI 要求：

- 读取对应记录
- 不修改原始数据
- 只追加 note 内容
- 保持世界观一致

---

# 五、MCP 记录与权限协议

MCP（Model Context Protocol）是绯界连接 AI 与世界数据的桥梁。

MCP 不负责创造故事，而负责提供安全、明确的数据访问方式。

流程：

```
房间页面
↓
生成 MCP 请求
↓
MCP 提供指定记录上下文
↓
AI 读取世界数据
↓
AI 生成回复
↓
MCP 写回指定字段
```

## 权限模型

绯界使用三类钥匙：

### Owner Key

用于：

- 管理自己的数据
- 上传同步记录

### Read Key

用于：

- AI 读取指定记录
- 只读访问

### Reply Key

用于：

- AI 写回生成内容
- 只能追加回复内容

---

# 六、AI 写回规则与记忆保护

原始事件数据属于世界记忆，不应被 AI 覆盖。

AI 生成内容只能写入扩展字段：

- note
- reply
- story
- letter

规则：

- 不覆盖原始记录
- 不删除历史记录
- 保留更新时间
- 保留同步信息

---

# 七、AI 任务请求模板

统一任务结构：

```
请读取我的绯界记录，并继续完成这一事件。

【模块】

【记录编号】

【记录ID】

【读取钥匙】

【回复钥匙】

请读取指定记录。
结合当前聊天已经加载的角色卡、世界书和近期记忆完成创作。

完成后，将内容写回指定 note 字段。

不要修改原始记录。
不要创建新记录。
不要处理其他记录。
```

# 八、导入与导出

所有房间支持 JSON 档案。

导出：

```
本地记录
↓
JSON 文件
↓
用户保存
```

导入：

```
JSON 文件
↓
校验结构
↓
合并历史
↓
更新记录
```

---

# 九、记录分类与同步规范

记录可以拥有：

- folder
- category
- tag

用于：

- 检索
- 展示
- 世界管理

同步时应考虑：

- 更新时间
- 内容指纹
- 本地修改
- 云端最新内容

避免旧数据覆盖新内容。
