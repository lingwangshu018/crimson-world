# 绯界 Git 仓库存档

这一文件夹专门保存“Git 仓库存档”功能的设计、配置格式、示例文件和后续实现代码。

它与绯界现有的默认云端、自定义服务地址分开，方便以后单独维护，也方便普通使用者只查看自己需要的部分。

---

## 这是什么？

Git 仓库存档允许你把绯界中的记录保存到自己创建的 Git 仓库里。

可以保存的内容包括：

- 我们的日记
- 绯夜酒馆与随杯手记
- 绯界咖啡馆与小剧场
- 时光之轮
- 旅行小兔与旅行信
- 皇家图书馆中的角色卡
- 皇家图书馆中的世界书
- 绯界可识别的备份清单与版本信息

Git 仓库存档既可以当作云端同步方式，也可以只作为长期备份箱使用。

> 强烈建议创建 **私有仓库**。公开仓库会让其他人看到日记、角色卡、世界书和其他记录。

---

## 三种使用方式

绯界会提供三种 Git 仓库存档方式。第一次使用时，请先根据自己的情况选择一种。

### 方式一：自动同步

适合：

- 希望点击一次就把记录同步到仓库的人
- 已经会创建仓库和访问令牌的人
- 经常在多台设备之间使用绯界的人

工作流程：

```text
绯界中的记录
→ 点击“同步到 Git 仓库”
→ 绯界通过平台接口更新 JSON 文件
→ 仓库自动产生一次提交记录
```

需要配置：

- Git 平台：GitHub、Gitee、GitLab 或兼容服务
- 仓库所有者
- 仓库名称
- 分支名称，通常是 `main`
- 存档目录，默认建议 `crimson-vault`
- 访问令牌

重要说明：

1. 访问令牌只保存在当前浏览器的本地配置中。
2. 访问令牌不会写进仓库。
3. 访问令牌不会进入导出的存档 ZIP。
4. 更换浏览器、清理浏览器数据或换设备后，需要重新填写令牌。
5. 请只授予“读取和写入目标仓库内容”所需的最小权限。

### 方式二：半自动存档

适合：

- 不想填写访问令牌的人
- 无法稳定访问自动同步接口的人
- 希望自己掌握每一次上传和下载的人
- 刚开始接触 Git 的普通使用者

上传流程：

```text
绯界
→ 导出“Git 仓库存档 ZIP”
→ 解压 ZIP
→ 打开自己的仓库
→ 上传解压后的文件
→ 提交更改
```

恢复流程：

```text
打开仓库
→ 下载仓库 ZIP
→ 回到绯界
→ 选择“导入 Git 仓库存档”
→ 选择刚下载的 ZIP
→ 检查导入预览
→ 确认合并
```

这种方式不需要令牌，也不依赖绯界替你调用 Git 平台接口。

### 方式三：纯本地仓库存档

适合：

- 完全不想连接云端的人
- 只想把绯界记录保存在电脑或移动硬盘里的人
- 希望以后再决定是否上传仓库的人

工作流程：

```text
绯界
→ 导出“Git 仓库存档 ZIP”
→ 保存到电脑、U 盘或移动硬盘
```

以后需要恢复时：

```text
绯界
→ 导入 Git 仓库存档
→ 选择之前保存的 ZIP 或 JSON
```

纯本地方式生成的文件与仓库方式完全兼容，所以以后可以直接上传到 GitHub、Gitee、GitLab 或其他 Git 服务。

## 小白应该选哪一种？

不确定时，按照下面选择：

| 你的情况 | 推荐方式 |
| --- | --- |
| 第一次使用，不懂令牌 | 半自动存档 |
| 不想联网，只想备份 | 纯本地仓库存档 |
| 会创建令牌，希望一键同步 | 自动同步 |
| GitHub 访问不稳定 | Gitee 半自动或自动同步 |
| 害怕误操作覆盖记录 | 半自动存档，并在导入前查看预览 |

第一次使用最推荐：**半自动存档**。

它不需要理解 API，也不需要把令牌交给网页，只需要会下载 ZIP、上传文件和导入文件。

## 创建自己的存档仓库

下面用通用步骤说明。GitHub、Gitee 和 GitLab 的按钮名称可能略有不同，但流程基本一致。

1. 登录你准备使用的 Git 平台。
2. 点击“新建仓库”或“创建仓库”。
3. 仓库名称可以填写：

```text
my-crimson-vault
```

4. 仓库可见性选择：

```text
私有 / Private
```

5. 可以勾选初始化 README，也可以保持空仓库。
6. 创建完成后，记下：
   - 你的用户名或组织名
   - 仓库名称
   - 默认分支名称，通常是 `main` 或 `master`

示例：

```text
平台：Gitee
仓库所有者：xiaotu
仓库名称：my-crimson-vault
分支：main
存档目录：crimson-vault
```

## 仓库中的标准目录结构

绯界导出的标准目录如下：

```text
crimson-vault/
├─ manifest.json
├─ records/
│  ├─ journal.json
│  ├─ tavern.json
│  ├─ cafe.json
│  ├─ time-wheel.json
│  └─ travel-rabbit.json
├─ library/
│  ├─ characters.json
│  └─ worldbooks.json
└─ backups/
   └─ crimson-backup-YYYY-MM-DD.json
```

各文件用途：

- `manifest.json`：说明这是绯界存档、格式版本和最后更新时间。
- `records/journal.json`：日记记录。
- `records/tavern.json`：酒馆记录和随杯手记。
- `records/cafe.json`：咖啡馆订单和小剧场。
- `records/time-wheel.json`：时光之轮记录。
- `records/travel-rabbit.json`：旅行记录和旅行信。
- `library/characters.json`：角色卡。
- `library/worldbooks.json`：世界书。
- `backups/`：完整备份快照，可用于紧急恢复。

不要随意改文件名。绯界会通过文件名自动判断内容属于哪个模块。

## 导入时会怎样处理？

导入前，绯界应显示预览，不会一选择文件就直接覆盖。

### 不同记录 ID

直接追加到本地记录中。

### 相同记录 ID

默认比较 `updatedAt` 或对应模块的更新时间：

- 导入文件更新：使用导入版本。
- 本地记录更新：保留本地版本。
- 时间相同但正文不同：列入冲突清单，让使用者选择。

### 角色卡和世界书

按照各自的 `id` 合并：

- 新 ID：新增。
- 相同 ID 且导入版本更新：更新。
- 相同 ID 且本地版本更新：保留本地。
- 无法判断：提示使用者选择。

### 删除操作

导入存档默认只合并和更新，**不会因为仓库里少了一条记录就自动删除本地记录**。

这能避免使用者下载了旧仓库后，把本机的新记录误删掉。

## 支持导入哪些文件？

绯界计划识别以下格式：

- 完整仓库 ZIP
- `crimson-vault` 文件夹压缩包
- 完整备份 JSON
- 单独的模块 JSON
- 单独的 `characters.json`
- 单独的 `worldbooks.json`

导入 ZIP 时，绯界应自动向下查找 `manifest.json`。因此从 GitHub、Gitee 或 GitLab 下载的仓库 ZIP，即使外面多包了一层仓库名称文件夹，也能正常识别。

## 自动同步配置字段

配置文件结构示例见：

```text
examples/config.github.json
examples/config.gitee.json
examples/config.local.json
```

主要字段说明：

| 字段 | 说明 |
| --- | --- |
| `mode` | `automatic`、`manual` 或 `local` |
| `provider` | `github`、`gitee`、`gitlab` 或 `custom` |
| `owner` | 仓库所有者用户名或组织名 |
| `repository` | 仓库名称 |
| `branch` | 目标分支，通常为 `main` |
| `directory` | 存档在仓库中的目录 |
| `apiBaseUrl` | 自定义 Git 服务的接口地址 |
| `tokenStorage` | 令牌存储策略，正式版固定为浏览器本地 |

配置文件本身不得包含真实令牌。

## 访问令牌安全说明

请务必遵守：

- 不要把令牌写进 `config.json` 后上传仓库。
- 不要把令牌截图发给别人。
- 不要把令牌放进角色卡、世界书或日记。
- 不要给令牌超出目标仓库所需的权限。
- 怀疑令牌泄露时，立即到 Git 平台撤销令牌并重新创建。

绯界导出时必须自动排除：

- Git 平台访问令牌
- 绯界所有者钥匙
- 绯界读取钥匙
- 绯界回复钥匙
- 浏览器保存的其他认证信息

仓库存档保存的是“记录和设定”，不是访问凭证。

## 没有 VPN 或 GitHub 打不开怎么办？

可以采用下面任一种方式：

1. 使用 Gitee 创建私有仓库。
2. 使用能正常访问的 GitLab 实例。
3. 使用半自动模式，在可访问仓库的平台上传和下载 ZIP。
4. 暂时使用纯本地方式，把 ZIP 保存在本机或移动硬盘。

存档格式与平台无关，所以以后更换平台时，不需要重新整理记录。

例如：

```text
Gitee 下载 ZIP
→ 导入绯界
→ 再导出标准 ZIP
→ 上传到 GitLab
```

## 常见问题

### 下载仓库 ZIP 后，绯界说没有识别到存档

检查 ZIP 内是否存在：

```text
manifest.json
```

或者：

```text
crimson-vault/manifest.json
```

不要只压缩一个空文件夹。

### 导入后出现重复记录

绯界依靠记录 `id` 去重。如果手动编辑 JSON 时修改了 ID，系统会把它当成新记录。

普通使用者不建议手动修改记录 ID。

### 换设备后自动同步不能用了

访问令牌只保存在原设备的浏览器里。新设备需要重新填写平台、仓库和令牌配置。

记录本身仍然在仓库中，不会丢失。

### 仓库里能不能直接编辑记录？

可以，但不推荐小白直接改 JSON。

手动编辑时必须保证：

- JSON 语法正确。
- 记录 ID 不随意修改。
- 时间字段使用有效时间格式。
- 文件编码为 UTF-8。

### 可以使用公开仓库吗？

技术上可以，但不推荐。

公开仓库里的日记、角色卡、世界书和剧情记录会被任何能访问仓库的人看到。

### 仓库删除后还能恢复吗？

只要本地还有导出的 ZIP 或 JSON，就能重新导入并创建新仓库。

因此建议偶尔下载一次完整 ZIP，保存在本机或移动硬盘。

## 开发目录说明

```text
git-archive/
├─ README.md
├─ schema/
│  ├─ config.schema.json
│  └─ manifest.schema.json
└─ examples/
   ├─ config.github.json
   ├─ config.gitee.json
   ├─ config.local.json
   └─ manifest.json
```

后续实现代码也应优先放在这一文件夹内，再由绯界控制中心调用，避免把 Git 平台适配逻辑散落到不同房间。

计划拆分为：

```text
git-archive/src/config.ts
Git 仓库存档配置读取与校验

git-archive/src/exporter.ts
生成标准目录和 ZIP

git-archive/src/importer.ts
识别 ZIP、JSON、预览冲突并合并

git-archive/src/providers/github.ts
GitHub 自动同步适配器

git-archive/src/providers/gitee.ts
Gitee 自动同步适配器

git-archive/src/providers/gitlab.ts
GitLab 自动同步适配器
```
